# 行途标准文章格式（xingtu-standard-article）

> 这份模板是「行途」公众号文章**行头 / 行尾 / 章内格式件**的唯一事实源（SSoT）。
> 写新稿时复制 `template.md`，按骨架填内容即可；排版交给 md2wechat CLI。

## 为什么需要它

一篇文章发出去，读者记住的往往不是内容，是**节奏**：开头三秒能不能抓住他、每章开头有没有一句摘要让他决定读不读、结尾有没有一份能带走的清单。
把这些位置固定成格式件，好处有三：

1. **读者预期稳定**——每篇都在同样的位置给同样的东西（结论 → 摘要 → 判断 → 清单）；
2. **写作有抓手**——不用每次重新想结构，填空即可；
3. **SEO / GEO 一致**——核心词在行头、摘要块、结论块、搜一搜注释里各出现一次，密度自然达标。

## 格式件清单（与引擎支持的对应关系）

| 位置 | 写法 | 引擎渲染（v2.4+） |
|---|---|---|
| 行头 · 短答案 | `> 一句话总结：…` | 引用块（GEO 短答案，前 1/3 位置） |
| 行头 · 结论前置 | `先说结论：…` | 普通段落 |
| 行头 · 目录 | `目录：` + 有序列表 | 伪列表（`1. ` 前缀 + 缩进，粘贴零损耗） |
| 章内 · 摘要 | `本章摘要：…` | **浅底摘要块**（左侧主色细线） |
| 章内 · 判断 | `个人观点：…` / `我的判断：…` | **强调观点块**（左侧主色粗线 + 浅色底） |
| 章内 · 口径 | `数据来源：…` / `数据口径：…` / `备注：…` / `注：…` | 小字灰色注释行 |
| 章内 · 配图 | `【配图：文件名.png】`（单独成段） | 图片占位卡（后台按位置插图） |
| 行尾 · 清单 | `# 本文核心结论` + 列表 | 小节标签 + 列表 |
| 行尾 · 预告 | `# 下一篇预告` | 小节标签 |
| 行尾 · 延伸 | `# 延伸阅读` + 链接列表 | 小节标签 + 外链转角标（微信禁外链） |
| 行尾 · 名片 | `# 关于行途` + builder 口径 + 点赞引导 | 小节标签 + 正文 |
| 行尾 · 署名 | 无需手写 | **引擎自动追加**（品牌行 / 排版引擎行 / 版权行） |
| 元信息 | `<!-- 搜一搜关键词：… -->` | HTML 注释，渲染时剥离，不进正文 |

## 使用方式

```bash
node bin/md2wechat.js 你的稿子.md -o 输出.html --theme pure
# 需要关掉署名页脚时：
node bin/md2wechat.js 你的稿子.md --no-signature
```

浏览器工作台（`index.html`）同一份引擎，粘贴到左侧即可看到同样的效果。

## 三条使用纪律

- **数字标来源**：每个数字后面写清来源与口径（`数据来源：` 行），第三方数据必须注明「第三方口径 / 非官方对比 / 数据截至…」。
- **观点标签克制**：`个人观点：` 全篇 3–5 处，每章最多一处；它标记的是判断，不是情绪。
- **格式件不新增语法**：全部用「标签：内容」这一种写法。新增语义前缀要先在 `lib/engine.js` 的 `SEM_BLOCKS` 里注册，再回写本文件——**顺序反了就会出现「写了样式却不生效」的静默失败**。
